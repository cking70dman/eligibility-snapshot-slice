IS-001 — UX Findings

Usability Findings

Pre-test heuristic findings and live session findings from IS-001 usability testing rounds.

Round 1 complete. 9 findings documented from participant sessions (P1). Pre-test heuristic findings are below. Process diagram findings will be added after the process description and diagram are published.

Pre-Test Findings

Four issues identified through heuristic review prior to formal participant testing. Logged as UF-PRE series.

ID Screen Theme Severity Evidence Recommendation
UF-PRE-001 /intake Consent gate bypassable via direct URL 3 — Major Direct navigation to /intake skips the consent checkbox on the landing page Add server-side consent gate or redirect unauthenticated /intake requests to landing page
UF-PRE-002 /intake result Result renders below the fold 2 — Moderate No auto-scroll or scroll indicator after Q6 submit — result panel renders outside viewport Add smooth scroll-to-result on submit, or render result on a dedicated screen with clear visual break
UF-PRE-003 /intake URL static throughout flow 1 — Minor All steps remain at /intake — results are not bookmarkable or shareable via URL Implement hash routing or route-per-question for result shareability
UF-PRE-004 /intake result Progress bar reads 100% on result render 1 — Minor Result state is not Q7 — the label is ambiguous and may confuse users about completion state Hide progress bar on result render, or replace with a "Complete" label / checkmark state

Round 1 Findings

Moderated think-aloud sessions with veteran participants (P1). 9 findings logged — UF-R1 series.

ID Screen Theme Severity Evidence Recommendation
UF-R1-001 /intake Q4 Means-test misconception drives self-disqualification 3 — Major Participants with higher incomes skipped the flow or selected “Prefer not to say” due to assumption that income thresholds disqualify them from all programs Add inline framing that income is used to match programs, not screen out — not all programs are means-tested
UF-R1-002 /intake Q3 Single-select goal forces wrong primary goal / restart 3 — Major Participants with multiple concurrent goals (e.g., prevent loss AND find affordable housing) could only select one; several selected incorrectly and wanted to restart Allow multi-select on the goal question, or reframe as “What is most urgent right now?” to reduce decision conflict
UF-R1-003 /intake all steps Load-bearing helper text goes unread 2 — Moderate Sub-copy below question headings (e.g., income scope definition, dependents definition) was consistently skipped; participants answered based on the heading alone Move critical definitions inline with options using info modals, or bold key terms in the sub-copy to interrupt scan behavior
UF-R1-004 /intake result No operating hours on crisis next-actions 3 — Major Crisis-branch result cards listed hotlines and walk-in centers with no hours; participants could not tell if resources were available at time of use Add operating hours (or “24/7” designation) to all crisis-branch next-action resources; flag if hours are unverified
UF-R1-005 /intake Q5 Dependents definition ambiguous 2 — Moderate Participants unsure whether to count a spouse, adult children living in the home, or financially dependent parents; several paused significantly or changed their answer Define “dependent” explicitly in the info modal: VA definition includes spouse and unmarried children under 18 (or in school/disabled); add examples for edge cases
UF-R1-006 /intake result Program names and acronyms opaque 2 — Moderate Result cards showed program names (HUD-VASH, SSVF, GPD) without explanation; participants read them aloud as questions, not as actionable pathways Add a one-line plain-language description beneath each program name on the result card; define acronyms inline on first use
UF-R1-007 /intake result Geographic scope ambiguous (Cook County vs. Chicago) 2 — Moderate Participants from suburbs (outside Chicago city limits but inside Cook County) were unsure whether results applied to them; one participant assumed results were “Chicago only” Add geographic scope label to the result header: “Programs available in Chicago and Cook County”; clarify where programs are county-wide vs. city-only
UF-R1-008 /intake Q3 result Crisis branch needs age-banded routing 2 — Moderate Crisis-branch results did not differentiate for age 55+ veterans; older participants noted that shelters and transitional programs shown were not appropriate for their situation Add age input or derive from context; route 55+ crisis profiles to senior-specific resources (SSVF, VA Community Care, Area Agency on Aging partnerships)
UF-R1-009 /intake Q4 Income field wording inconsistent 1 — Cosmetic Question heading said “annual household income” but sub-copy said “include all household members”; participants read these as potentially different scopes Standardize wording: use “annual gross household income (all members)” in both the heading and sub-copy

Severity Scale

1 Cosmetic — Does not affect task completion; fix if time allows
2 Moderate — Causes friction or confusion; fix before next round
3 Major — Significantly impairs task completion; prioritize fix
4 Blocker — Prevents task completion; must fix before any testing
